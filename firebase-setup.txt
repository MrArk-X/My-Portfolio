FIREBASE SETUP — step by step
==============================

1. Go to https://console.firebase.google.com, sign in with a Google
   account, click "Add project". Free "Spark" plan is fine — accept
   the defaults, no credit card needed.

2. Left menu -> Build -> Firestore Database -> "Create database" ->
   start in PRODUCTION mode -> pick any region -> Enable.
   (This is your database — projects, certificates, journal posts,
   profile, and messages all live here.)

3. Left menu -> Build -> Storage -> "Get started" -> production
   mode -> Done.
   (This is where uploaded photos will actually live, instead of
   being stuck inside one browser.)

4. Left menu -> Build -> Authentication -> "Get started" -> under
   "Sign-in method" enable "Email/Password" -> Save.
   Then go to the "Users" tab -> "Add user" -> enter YOUR real email
   and a real password. This becomes your new admin login, replacing
   the hardcoded MrArk-X one.

5. Click the gear icon (top left) -> "Project settings" -> scroll to
   "Your apps" -> click the </> (web) icon -> give it any nickname ->
   register app (skip Firebase Hosting — you're keeping GitHub Pages).
   You'll be shown a block of code containing a firebaseConfig object
   with apiKey, authDomain, projectId, storageBucket, etc.
   COPY THAT WHOLE OBJECT and send it to me — that's all I need to
   wire the site up. (It's fine that it's public-looking; the real
   protection is the rules below, not secrecy.)

6. Still in the console: Firestore Database -> "Rules" tab -> replace
   the contents with the FIRESTORE RULES block below -> Publish.

7. Storage -> "Rules" tab -> replace the contents with the STORAGE
   RULES block below -> Publish.

That's it — steps 1-7 usually take under ten minutes total.


FIRESTORE RULES (paste into Firestore -> Rules)
================================================
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /profile/{id} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /projects/{id} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /certificates/{id} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /journal_posts/{id} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /messages/{id} {
      allow create: if true;
      allow read, delete: if request.auth != null;
      allow update: if false;
    }
  }
}


STORAGE RULES (paste into Storage -> Rules)
============================================
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /photos/{allPaths=**} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}


WHAT THESE RULES MEAN, IN PLAIN TERMS
======================================
- Anyone visiting the site can READ projects, certificates, journal
  posts, and your profile — and can SEND a message.
- Only someone signed in as the admin (you, via the email/password
  from step 4) can ADD, EDIT, or DELETE anything, or READ the
  messages people have sent.
- No schema/table setup needed like Supabase's SQL — Firestore
  creates each collection (projects, certificates, etc.) the first
  time a document is added to it, automatically.
